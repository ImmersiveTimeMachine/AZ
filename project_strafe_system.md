## The chain (one tag drives everything)
`FAZ_QuickSlot.bStrafeOnEquip` (tick on the fist slot in `BP_AZ_PlayerController` QuickBar) → on equip `EquipSlot` calls `ASC->AddStateTag(Movement.Strafe)` (replicated state tag; `AddStateTag/RemoveStateTag` PUBLIC on `UAZ_AbilitySystemComponent`). `ChooserContext.bStrafe = OwnedTags.HasTag(Movement.Strafe)`; CHT col 11 = bStrafe BoolColumn. `CustomInputs.RotationMode = Strafe` carries it to the Mover walking mode.

## ★ Strafe ROTATION (FINAL design — settled after MUCH iteration)
**Model: HOLD at idle, smooth SPRING-align to the camera on move.** NOT continuous-follow, NOT turn-in-place.
- `ProduceInput` (`AZ_PawnMoverHeroCharacter`): `bStrafe` → idle (no move input) sets `OrientationIntent = current actor facing` (HOLD, no rotation); moving sets `OrientationIntent = camera-forward`. An **align LATCH** (`bStrafeAligning`) keeps facing the camera until the body is within `AlignExitDeg`(5°) **even across a tap release**, so one tap aligns FULLY (no part-way freeze / multi-tap creep).
- Walking mode (`AZ_PawnMovementMode_Walking::GenerateWalkMove`): strafe → `FacingSmoothingTime = StrafeFacingTime`. The parent `USmoothWalkingMode` spring rotates the body toward `OrientationIntent`. This IS CMC's `bUseControllerDesiredRotation` (StrafeFacingTime = RotationRate analog). **`StrafeFacingTime` is BP-exposed** (mode, `AZ|Walking|Facing|Strafe`, default 0.10s; →0 ≈ instant lock).
- **MovementDirection = camera-INTENT, not velocity-vs-body** (`AZ_MoverAnimInstance`): in strafe the directional clip is bucketed from `MoveIntentWS` (keyboard) vs the CAMERA, not `PredictedFutureVelocity` vs the body. So "W=forward" is right the instant pressed even while the body is still rotating to the camera (velocity-vs-body would read a side/back clip until the body caught up). Explore still uses velocity-vs-body.
- **★★ THE KEY FIX (the "double alignment" / "small turn then 1s realign"):** the strafe START is a transition, and transitions queue the RM move `FLayeredMove_RootMotionAttribute` (MixMode **OverrideAll**). OverrideAll REPLACES the capsule's whole move INCLUDING rotation for the clip's whole length (~1s) → it **suppresses the facing spring** → the body did the start clip's motion for ~1s, and only AFTER the clip ended did the spring rotate to the camera = the double. **Fix: exclude strafe starts from the RM move** (`bStrafe && SMState==TransitionToLocomotion` skipped in the RM bridge) → the spring aligns from the FIRST moving frame; the start clip plays cosmetically, capsule is velocity-driven (like the loops). Explore starts KEEP RM (their turn-start clips need the baked root motion).
- SM (`UAZ_LocomotionStateMachine`): strafe SKIPS body-turning starts + reversal pivots (`bStrafe` forces `StartDirection=Fwd`, no bucketing, no `bHardTurn` pivot) — direction changes just switch the directional loop.

### Idle turn-in-place — TRIED then REMOVED (don't rebuild it)
Built a full hold-then-turn (90° commit deadzone + `IdleTurnLeft/Right` SM states + RM 90° turn clips). **Removed.** Why: (1) RM rotation **snaps back on Mover re-sim** — the RM-attribute move reads root motion from the MESH, which can't be reproduced during prediction reconciliation (engine documents this, `RootMotionAttributeLayeredMove.cpp:81` "for fixed-tick modes the attribute would be better as an accumulator"); proven via diag (actorYaw climbed 6→91 then snapped to 6 every cycle). (2) Any hold-at-idle DEADZONE inherently creates a move-start "double" (idle pose off-camera → must realign on move). The user settled on hold + smooth spring-align instead. `EAZ_StateMachineState::IdleTurnLeft=10/IdleTurnRight=11` left **VESTIGIAL** (ABI; no path emits them); dead CHT rows 77/78 still map them → **cleanup pending** (delete rows + turn-clip refs).

## Gotchas burned (don't repeat)
- **RM-attribute rotation is unreliable under Mover prediction** — `FLayeredMove_RootMotionAttribute` (OverrideAll) reads root motion from the mesh; it (a) **snaps back on re-sim** for sustained rotation (idle turn) and (b) **suppresses the facing spring for the move's whole duration** (the strafe-start "double"). Use RM for translation/short bursts; drive ROTATION via `OrientationIntent` + the mode spring (in the networked InputCmd → deterministic). Engine note: `RootMotionAttributeLayeredMove.cpp:81`.
- **CMC↔Mover rotation map:** `bOrientRotationToMovement` = OrientationIntent=velocity (explore); `bUseControllerDesiredRotation` = OrientationIntent=control-rot + `SmoothWalkingMode` spring (`FacingSmoothingTime`=RotationRate) (strafe); `bUseControllerRotationYaw` = FacingSmoothingTime→0 (instant). There's no magic Mover flag — you set OrientationIntent.
- **`bLoop=True`** required on directional/turn LOOP clips (ship as one-shots → freeze). Clips are in **gitignored** `Content/Assets/RTG_AZ/` → fix is LOCAL-ONLY.
- **MCP Python:** `does_asset_exist`/`EditorAssetLibrary.load_asset` FLAKY → use `unreal.load_asset`. DB save needs `save_loaded_asset(db, only_if_is_dirty=False)`. Verify DB content/ABP assignment via `unreal_asset_dependencies` (CDO/PSD lists not Python-exposed).
- **Stale makefile after Live Coding** → `git status --short -- Source/AZ | awk '{print $2}' | xargs touch` then rebuild. **Live Coding repeatedly refused the 2nd+ `LiveCoding.Compile` this session** — for anything beyond one body-edit, prefer close-editor + CLI build (reliable).
- **MM is for DISCRETE state→clip by trajectory**; continuous overlays (turn, lean) do NOT belong in MM (pose-tilt clips → per-frame L/R flip-flop).
