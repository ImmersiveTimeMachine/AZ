# Аудит подхода к UI

**Последнее решение пользователя:** перенос отложен, сейчас не выполнять. Общая запись — [TD-001 в TECH_DEBT.md](../TECH_DEBT.md). Ниже результаты аудита и предварительная последовательность, а не активный план миграции.

Правило пользователя: всё оформление, которое можно редактировать в виджетах, делать в Widget Blueprint/UMG. C++ хранит игровые правила, данные, проверки и транзакции. Сам вызов CreateWidget из C++ — нормальное создание экземпляра готового класса, а не признак программной вёрстки.

| Блок | Проверенное состояние | Что переносить |
|---|---|---|
| Осмотр | AZ_InspectionPanel::RebuildWidget строит дерево в C++, Component создаёт native StaticClass | Первым: весь layout, полосу, карточку чтения, blur и переходы — в WBP; native оставляет сессию, вращение, владение/Take, адаптер данных |
| Крафт | AZ_CraftingPanel::RebuildWidget строит карточку/текст/кнопки; InventorySwitcher создаёт native панель и кнопку Craft | Вторым: WBP_CraftingPanel и дизайнерская кнопка входа, с задаваемым WidgetClass |
| Пауза/настройки/подтверждения | WBP_AZ_MenuRoutes назначен в контроллере, но AZ_MenuRouteWidget строит fallback-дерево и строки команд/настроек программно | Дизайнерские страницы/шаблоны строк, C++ передаёт маршрут и значения настроек |
| HUD | WBP_AZ_GameHUD назначен в контроллере; есть BindWidget | Вынести FitWeaponHUD, фиксированные позиции/размеры и смену размера шрифтов в WBP; проекцию world point можно оставить вычислением данных, отступы/оформление сделать редактируемыми |
| Quick Select | Authored WBP_AZ_QuickSelect и Entry-классы, заполнение из C++ | Убрать hardcoded PlaceCardWidget/PlaceKeyBadge и оформление пульса из C++; оставить режимы выбора и остатки предметов |
| Инвентарь | WBP_GameInventoryMenu/Switcher, клетки/всплывающие меню/показатели имеют BindWidget | Сохранить существующий подход, отдельно вынести программную кнопку Craft и обнаруженные стилевые overrides. Транзакции не переносить |
| Карта/журнал | WBP_QuestMapPage/QuestJournalEntry существуют; native динамически создаёт entries | Динамическое заполнение оставить через заданные WBP-классы; заголовки/строки/отступы/цвета — шаблоны и данные стиля. Не считать fallback RebuildWidget доказательством использования, если активный WBP уже имеет дерево |
| Подсказки и индикатор удержания | WBP_FN_ActionPrompt_Overlay/Paper и WBP_AZ_InteractionHold — реальные authored UMG | Уже близко к правилу. CommonUI/GAS input и реальный прогресс остаются в коде; графика/анимации/размеры — в виджетах |

Проверка: поиск ConstructWidget/RebuildWidget/BindWidget и литералов компоновки в Source/AZ/{UI,InventoryUI,WorldInteraction}; реестр owned WidgetBlueprint и назначенные классы контроллера прочитаны из открытого проекта. Это аудит текущих игровых экранов, не утверждение, что каждый сторонний пакет проекта проверен.

Перенос не выполнялся этим аудитом. Последняя просьба пользователя: сначала собрать текущий осмотр, затем перенести оформление, сохранив логику. Для последующей миграции нужны BindWidget-контракт, класс панели в компоненте, событие обновления view и дизайнерские шаблоны; не оставлять параллельный C++ layout, который перезапишет UMG. Правило закреплено в AGENTS.md.

Блюр пока находится в BP_AZ_PlayerController → компонент Inspection → Presentation. EnvironmentBlurStrength и BlurTransitionSeconds являются редактируемыми свойствами; их настройка не требует пересборки C++. При переносе экрана в UMG нужно выбрать одно место хранения настроек, а не оставлять конкурирующие значения. Пользователь открыл эти настройки и меняет значения; на момент последнего readback они равны 10 и 1 секунде, агент их не менял и не сохранял пользовательские правки.
