# CHALK — завершение системы метания

Актуализация 25 сентября: крафт зажигательного игрового предмета и горение противника теперь явно требуются пользователем. См. [актуальный план реализации](C:/UnrealEngine/Games/AZ/docs/design-briefs/throwable-completion-plan-v2.md). Прежнее предложение отложить крафт больше не определяет этот проход.

Приоритет пользователя: сначала закончить метание, затем перейти к дизайну большого блока взаимодействий с окружением. Этот список фиксирует направление следующей работы; перед реализацией требуется сверить уже существующие классы, определения предметов, анимации и поведение. Не считать пункты доказательством полного отсутствия реализации.

## Начальный список предметов

| Предмет | Ожидаемое поведение для согласования |
|---|---|
| Граната | Сохранить работающий бросок, взрыв, урон и интеграцию разрушения; проверить крайние случаи |
| Камень | Подбор, выбор, прицеливание, бросок, удар/шум, остановка и возможность повторного подбора |
| Обычная стеклянная бутылка | Подбор, бросок, звук отвлечения, разбивание при подходящем ударе; решить поведение при мягком падении |
| Зажигательная бутылка | Отдельный игровой тип: подготовка, бросок, разбивание, визуальная область огня и игровые последствия; правила отмены и расхода предмета |

Игровой крафт зажигательной бутылки — отдельная зависимость: абстрактный рецепт из игровых ресурсов, стоимость, интерфейс и момент списания. Состав, количества и реальный способ изготовления не нужны для игрового дизайна.

## Общая основа

1. Аудит текущей гранаты и существующего обобщённого throwable-кода; проверить, что уже поддерживается для камня/прочих типов.
2. Типы и данные предмета: масса/размер, траектория, отскок, реакция на контакт, шум, ломкость, возможность возврата, эффект после остановки.
3. Единый цикл: подбор → выбор → подготовка → прицеливание → бросок либо отмена → результат. Не делать по независимой способности для каждого похожего предмета без причины.
4. Анимации и занятость рук: без оружия, с пистолетом/винтовкой, стоя/присев; проверить уже согласованные правила движения.
5. Контакт и результат: шум для ИИ отдельно от урона; обычный предмет не должен случайно взрываться. Разрушение бутылки и квестовое событие выдаются один раз. Пользователь явно требует реакции врагов: камень/бутылка привлекают внимание к месту удара, взрыв вызывает соответствующую угрозе реакцию. Проверить существующий слух и поведение, затем описать слышимость, приоритет текущего боя, повторные стимулы и возвращение после поиска; не раскрывать бросившего без воспринимаемых оснований. Точные реакции остаются предметом дизайна.
6. Инвентарь: точный расход одного предмета, отсутствие дубликатов, восстановление идентичности повторно подбираемого предмета. Для каждого типа определить момент расхода/необратимой активации: отмена до него не теряет предмет; поведение после него согласовать отдельно, без автоматического возврата уже брошенного или активированного предмета.
7. Управление и интерфейс: клавиатура/мышь и геймпад, корректные подсказки, быстрое меню, смена типа предмета.
8. Сохранение: количество в инвентаре и судьба предметов в мире; отдельно определить правила для летящих/горящих объектов при загрузке.
9. Проверка пользователем: близкий/дальний бросок, стены и потолки, отмена, смена предмета, попадание/промах, повторный подбор, полный инвентарь, сохранение/загрузка.

## Порядок для обсуждения

Сначала аудит общей основы и камень; затем обычная бутылка и отвлечение; затем зажигательный игровой предмет и его крафт/огонь; после — общий проход по всем четырём типам. Конкретные анимации, параметры и объём огненной системы пока не согласованы.

Граница этапа: работоспособность бросаемого предмета и полноценная RPG-экономика — разные критерии. На следующем обсуждении выбрать, нужен ли уже минимальный игровой рецепт или сначала готовый предмет для проверки броска. Не расширять этот этап автоматически до дерева развития, общего крафта или системного распространения огня.

Не расширять автоматически этот проход ножом, сетью или произвольным бросанием всей мебели: в старых документах могли быть другие планы, но здесь пользователь назвал четыре начальных типа. Дополнительные типы добавлять после уточнения.
