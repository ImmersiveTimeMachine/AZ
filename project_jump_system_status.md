The air was the ONLY jump phase selected by trajectory-MM; takeoff (r29-33) and land (r35-39) were already gait/foot-selected by the chooser. **Fix: make the air chooser-driven too.**

## TRUE ROOT CAUSE OF THE ENTIRE IN-AIR SAGA (2026-06-06) — a FULL Blend Stack node NESTED INSIDE the sample graph

The ABP's outer `Blend Stack` node has a per-sample inner graph; that graph contained a **second FULL `Blend Stack` node** (AnimationTime pin = literal 0) where a **`Blend Stack Input`** node belongs. Effects:

## HYBRID JUMP PROTOTYPE (implemented 2026-06-07, A/B vs pure physics — superseded by FINAL above; physics branch kept on bUseHybridJump=false)
**Design: RM rise → physics fall.** Jump press → `UAZ_PawnMoverComponent::Jump()` (override, reached via bHandleJump pre-sim path) branches on **`bUseHybridJump`** (UPROPERTY, default true): hybrid → `QueueNextMode("RMAction")`; false → the gait-scaled impulse (`JumpUpwardsSpeedWalk/Run/Sprint` = 350/500/550, also added 2026-06-07). Hybrid flow: RMAction maps to InAir → SM TransitionToInAir → takeoff row pushes the Start clip from **ST=0** (anticipation VISIBLE — capsule grounded through the crouch because the clip RM says so) → the RM bridge (un-gated for TransInAir when `bHybridJumpActive`) queues the OverrideAll root-motion move (duration=remaining clip) → the clip's baked arc lifts the capsule (per-gait arcs free) → **`UAZ_PawnMovementMode_RMAction` apex handoff**: `bHandOffToFallingAtApex` (default true; set FALSE for vault/mantle) watches the proposed RM Z-delta — after net rise >10cm, 2 consecutive non-positive ticks = apex → `OutputState.MovementEndState.NextModeName="Falling"` (+ `MaxRiseSeconds=1.0` safety) → physics descent (terrain-adaptive, air control) → land MM. The AnimInstance cancels the RM move on the observed RMAction→Falling edge (`LastRawMoverModeName` tracking; under Falling the engine only strips the move's Z — horizontal would fight air control). Apex-detection state lives on the mode instance — NOT NP-rollback-safe (prototype; move to sync state if MP jitter).
**Chooser coupling:** hybrid expects takeoff ST=0; the physics branch expects launch-frame STs (idle 0.175, walk 0.15/0.15, run RU 0.117 / LU 0.217 — measured root-Z-leaves-ground). Flipping the A/B toggle properly means flipping the takeoff STs too.
**Why hybrid:** physics jump needed two sync patches (anticipation-skip STs + gait impulse) because it decouples capsule from anim; RM rise makes both impossible-by-construction while the physics fall keeps terrain adaptivity (the original RM-jump killer was the OPEN-LOOP fall: float-then-drop). Full-RM remains rejected — long fall clips don't tell the capsule where the floor is.

## AIR "REPLAY" BUG — exclude must cover to the TRUE apex (FIXED 2026-06-05)

## Gotchas learned (PoseSearch authoring via Python)
- **Chooser cell edits: verify against DISK, not memory (learned 2026-06-07).** Two failure modes seen the same night: (1) setting a BOOL INPUT cell re-sorts rows IMMEDIATELY → a second set-by-index in the same script can hit the wrong (moved) row — always re-locate the row BY ASSET before every set; (2) an OutputStruct field edit (`bUseMM=True`) read back True in-memory after `compile_and_save -> True` yet was FALSE after editor restart — after any batch of chooser edits, `EditorLoadingAndSavingUtils.reload_packages([pkg])` and re-dump to confirm the serialized state.
- **Jump takeoff sync (2026-06-07):** the physics impulse is instant but Start clips carry 0.12-0.22s of authored anticipation-crouch → capsule rises while the anim still squats (the "inertia" desync). Fix: takeoff rows direct-play from the MEASURED launch frame (first t where root-Z>3cm rising: idle 0.175, walk 0.150 both, run_RU 0.117, run_LU 0.217) with BT=0.1. Re-measure if clips change. (Anticipation is intentionally skipped — restoring it would require delaying the impulse, a gameplay-feel decision.)
- **Sync does NOT remove ORPHANED synced entries (learned 2026-06-07).** If a clip's BranchIn notify is deleted, its synced DB entry is NOT auto-removed on the next DB save — the sync only reconciles entries whose sequence still appears in the registry referencer list; orphans are kept as "not requiring synchronization". Remove them explicitly (`RemoveAnimationAtIndex`) after stripping BranchIns. Also: a rename leaves the registry referencer data stale briefly — verify with `GetReferencers` before trusting a sync result.
- **BranchIn↔DB membership is AUTO-SYNCED by the engine (learned 2026-06-06).** `UPoseSearchDatabase::PreSaveRoot` → `SynchronizeWithExternalDependencies()` rebuilds the entry list from asset-registry REFERENCERS: every `BranchIn(Database=this)` notify on a saved sequence yields ONE synced entry whose **SamplingRange = the notify window** (whole-clip window → full range) keyed by BranchInId. Consequences: (a) explicitly-added entries are NOT deduped against synced ones → explicit + BranchIn = **DOUBLE entries on the next DB save** (hit: 15→30); (b) wiping BranchIn notifies silently REMOVES the synced entries on the next DB save (how the DB dropped 15→7 unnoticed during the 06-05 debugging). **Rule: a clip with a BranchIn must NOT also be explicitly added — the notify owns membership. Populate = add BranchIn notifies → save clips → save DB (sync fills the list). Verify: entry count == total BranchIn notifies; a mismatch reveals stray/duplicate notifies.** Right after an editor restart the registry may need a minute before sync finds the referencers (a save then yields 0 — just re-save).
- **Anim Notifies are engine-protected from Python reads** (`notifies` property errors). ADD them via `UAZ_PoseSearchUtils` C++ helpers (`AddExcludeFromDatabaseNotify`, `AddBlockTransitionNotify`, `AddModifyCostNotify`, `AddOverrideContinuingPoseCostBiasNotify`, `RemoveAllPoseSearchNotifies`). Can't read them back — track ranges yourself.
- **`extract_root_motion` is NOT on `AnimSequence`.** To sample a clip's vertical arc: `unreal.AnimationLibrary.get_bone_pose_for_time(seq, "root", t, True)` → `.translation.z` (root bone with extract_root_motion=True gives world body Z). Foot bones return local (≈0) — useless for height.
- **Creating a `PoseSearchDatabase` via `AssetTools.create_asset(..., PoseSearchDatabaseFactory())` returns None.** Instead DUPLICATE an existing DB (`EditorAssetLibrary.duplicate_asset`), `AZ_PoseSearchUtils.clear_database`, then `add_sequences_to_database`. Inherits schema + settings.
- **`asset_search class_filter="PoseSearchDatabase"/"PoseSearchSchema"` returns 0** (registry class-name mismatch) — find them via `asset_referencers`/`asset_dependencies` or name_pattern instead.
- After changing a clip's PoseSearch notifies, **re-save the DB** so it re-indexes; verify by opening the DB asset (excluded ranges show greyed).
